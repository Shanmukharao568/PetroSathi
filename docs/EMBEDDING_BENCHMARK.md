Generated by `npm run rag:benchmark` on 2026-11-07T20:49:35.269Z. Machine: local CPU (no GPU). Quantized (q8) ONNX models via transformers.js.

**Corpus:** 4 demonstration documents (English), 18 chunks, produced by the production extraction and chunking pipeline (chunk 1000 / overlap 200).

> Caveats: the corpus is small and synthetic, and the queries were written for this benchmark. The results compare candidates; they do not measure production accuracy. Re-run on your approved manuals before relying on the threshold.

## Cost and deployment

- Both candidates run locally on CPU inside the Node API: no API key, no per-query cost, and no document text leaves the server.
- First use downloads the quantized weights from Hugging Face into `MODEL_CACHE_DIR`. After that the server works offline.
- Memory: roughly 200–400 MB of RAM per loaded model.

## History

- First run (2026-11-08), before a chunker fix: e5-small Recall@5 0.857 / MRR@5 0.492; MiniLM Recall@5
  0.750 / MRR@5 0.606. Many queries' top hit was a **title-only chunk**, a document title emitted as its
  own chunk because it was followed directly by another heading. The chunker now carries body-less
  headings into the next chunk. That pipeline bug affected both models; the numbers above are after the fix.

## Decision

**Chosen: `Xenova/multilingual-e5-small`.** It ranks first on overall MRR@5, with cross-lingual recall as the tie-break, then latency. Set `EMBEDDING_MODEL` to override. Changing the model requires reprocessing documents, because each model has its own Chroma collection.
